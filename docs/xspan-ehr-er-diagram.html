PostgreSQL Production Features

What this schema gives your engineers beyond the SQLite version:

Enums for Data Integrity

20+ PostgreSQL enums ensure only valid values enter the database. No more "actve" typos breaking queries.

clinical_status_enum severity_enum med_status_enum encounter_class_enum

CHECK Constraints on Every Metric

Every numeric field has range validation. Heart rate must be 20-300 bpm. SpO2 must be 50-100%. Prevents garbage data at the DB level.

heart_rate BETWEEN 20 AND 300

GENERATED Columns (Auto-Computed)

BMI and waist-hip ratio are auto-computed from their inputs. No application code needed.

bmi GENERATED ALWAYS AS (weight_kg / (height_cm/100)^2) STORED

Partial Indexes for Common Queries

Indexes only on the rows engineers actually query. Active meds, active conditions, unacked alerts, pathogenic variants, failed syncs.

WHERE clinical_status = 'active' WHERE acknowledged = FALSE

Auto-Link Trigger (lab_results to lab_reference)

When a lab result is inserted with a LOINC code, a trigger auto-populates the lab_ref_id FK. Engineers never need to look up the reference table manually.

JSONB for Flexible Nested Data

Encounter diagnoses, care plan goals, microbiome species lists — stored as queryable JSONB, not opaque TEXT.

diagnoses JSONB goals JSONB top_species JSONB

7 Pre-Built Views

Common queries pre-defined: v_active_medications, v_active_conditions, v_latest_vitals, v_abnormal_labs, v_pending_alerts, v_pathogenic_variants, v_health_trend_90d

Cascading Deletes

Delete a patient and all their data goes with them. Delete a data source and all records from that source are removed. GDPR-ready.

ON DELETE CASCADE

Encrypted Token Storage

OAuth tokens stored as BYTEA for pgcrypto encryption. Not plaintext.

Auto-Computed Sync Duration

sync_log.duration_ms auto-computed from start/complete timestamps. No application math needed.

TEXT[] Arrays for Multi-Value Fields

Allergy manifestations stored as native PostgreSQL arrays. Query with ANY() or @> operators.

manifestation TEXT[] sources TEXT[]

Table Comments for Onboarding

Every table and view has a COMMENT ON description. Run \dt+ or \dv+ in psql to see them.

Key Queries Your Engineers Will Write

Dashboard Trend Charts

SELECT * FROM v_health_trend_90d WHERE patient_id = $1

Returns 90 days of daily snapshots with all vitals, sleep, activity, glucose, and composite scores.

Smart Nudges: Drift Detection

SELECT * FROM v_pending_alerts WHERE patient_id = $1

Unacknowledged alerts like "HRV down 14% from 30-day average". Severity-sorted for priority.

Drug-Gene Interactions

SELECT m.medication_name, g.gene, g.clinical_significance FROM v_active_medications m CROSS JOIN genomic_variants g WHERE g.is_pharmacogenomic AND g.patient_id = m.patient_id

Abnormal Lab Trend

SELECT test_name, value_numeric, recorded_at FROM lab_results WHERE patient_id = $1 AND loinc_code = '4548-4' ORDER BY recorded_at

HbA1c over time — power a line chart showing metabolic trend.

Multi-Source Cardiovascular Synthesis

SELECT date, resting_hr, hrv, bp_systolic, bp_diastolic, cardiovascular_score FROM daily_snapshot WHERE patient_id = $1 ORDER BY date DESC LIMIT 30

HR from Apple Watch + HRV from Oura + BP from Omron + labs from b.well = one unified view.

Patient Clinical Summary (for Health Passport)

Join v_active_conditions + v_active_medications + v_active_allergies + v_latest_vitals + most recent lab_results = complete clinical picture.
